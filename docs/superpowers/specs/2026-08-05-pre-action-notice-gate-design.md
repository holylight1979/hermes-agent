# 執行前白話預告強制閘門設計

## 目標

當設定開啟時，任何模型工具呼叫在實際派送前，都必須先有使用者可見的繁體中文預告，至少包含：

1. `執行目標：`：說明當下要完成的具體事情。
2. `預估` 或 `概估`：提供粗略所需時間。

若預告缺失或格式不完整，Hermes 不得執行該批工具。

## 範圍

- 套用至同一代理核心下的 CLI、Gateway、API Server 與其他 session 入口。
- 套用至所有模型發出的可見工具批次，包括終端、檔案、瀏覽器、子代理、外部程式代理與澄清工具。
- 純文字回答、Hermes 自身啟動程序與非模型工具的內部維護動作不受此閘門影響。
- 功能以設定開關控制，預設關閉，避免改變其他使用者的既有行為；目前 `default` profile 明確開啟。

## 設定

新增正式設定鍵：

```yaml
agent:
  require_pre_action_notice: false
  pre_action_notice_max_retries: 2
```

目前 profile 將設為：

```yaml
agent:
  require_pre_action_notice: true
  pre_action_notice_max_retries: 2
```

設定必須納入 Hermes 的預設設定與正式鍵驗證，不得依賴未識別的自訂鍵警告。

## 執行流程

1. 模型回傳一個或多個工具呼叫。
2. 閘門在任何工具派送之前檢查該回合的可見文字。
3. 合格條件：
   - 文字非空。
   - 包含 `執行目標：`。
   - 包含 `預估` 或 `概估`。
   - 目標標籤後有實質內容，不接受只有標籤。
   - 時間欄位後有實質內容，不接受只有標籤。
4. 合格：維持原工具呼叫與既有串流／持久化流程，不增加 API 請求。
5. 不合格：
   - 捨棄本次尚未執行的工具呼叫，不得寫入正式 session 紀錄。
   - 以現有的臨時恢復鷹架建立合法的 assistant → user 角色交替。
   - 使用者角色的內部提示要求模型先輸出符合格式的繁中預告，並重新發出原本需要的工具呼叫。
   - 內部恢復訊息須標記為 ephemeral，不進入持久 session、不污染壓縮摘要與使用者意圖判定。
6. 最多重試 `pre_action_notice_max_retries` 次。
7. 若重試耗盡仍不合格：
   - 不執行任何工具。
   - 向使用者顯示明確停止原因：模型未提供必要的執行前預告。
   - 回合以可辨識的失敗狀態結束，不得顯示成功。
8. 任一合格工具批次完成派送後，連續重試計數歸零。

## 重要不變量

- 沒有合格預告，就沒有工具副作用。
- 不以通用 UI 假字串冒充模型已解釋具體目標。
- 不把未執行的 assistant(tool_calls) 寫回 API 對話，避免缺少 tool result 的非法配對。
- 不破壞 assistant/user 角色交替。
- 不改寫已存在的歷史訊息，不破壞長期提示快取。
- 功能關閉時，行為與目前版本一致。

## 使用者可見行為

合格範例：

```text
執行目標：讀取目前設定與近期錯誤紀錄，確認服務無法啟動的原因。預估約 2–4 分鐘。
```

不合格回合在重試期間可顯示短狀態訊息，例如：

```text
正在要求代理補上執行目標與時間預估；尚未執行任何工具。
```

重試耗盡：

```text
已停止：代理未提供必要的執行前預告，因此沒有執行工具。
```

## 測試策略

### 單元／整合測試

1. 設定關閉：空白內容加工具呼叫仍走既有行為。
2. 設定開啟、首次合格：工具只執行一次，沒有額外 API 回合。
3. 設定開啟、首次空白：工具完全不執行，產生 ephemeral 重試。
4. 第二次合格：只執行重試回合的新工具呼叫一次。
5. 重試耗盡：工具執行次數為零，回傳明確停止訊息。
6. 缺目標、缺時間或只有標籤：均判定不合格。
7. 多工具批次：整批在閘門前被阻擋，不得部分執行。
8. ephemeral 恢復訊息不寫入 session DB、不進入壓縮的人類意圖來源。
9. CLI 與非串流 one-shot 路徑皆保留可見預告。
10. 既有 dropped-tool-call、空回應、角色交替與工具派送測試不得退步。

### 端到端驗證

以全新 session 要求執行無害的 `PREACTION_SMOKE_OK` 命令：

- 原始失敗基準已證明 assistant 內容為空且工具直接執行。
- 修正後必須在 session DB 中看到：合格的 assistant 預告／工具呼叫，接著才是 tool result。
- 終端畫面必須在工具輸出前顯示同一段預告。
- 若刻意使用測試模型連續回傳空白工具回合，必須看到停止訊息且命令從未執行。

## 實作邊界

- 優先擴充 `agent/conversation_loop.py` 既有恢復框架與相關設定／測試。
- 不新增模型工具，不修改工具 schema。
- 不新增外部服務、背景程序或另一套對話引擎。
- 不修改使用者的 JARVIS 專案。
- 不推送遠端；只在本機 Hermes 工作樹留下可檢查的提交。

## 回復方式

- 將 `agent.require_pre_action_notice` 設為 `false` 可停用行為。
